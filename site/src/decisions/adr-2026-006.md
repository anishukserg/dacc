# adr-2026-006 — Спецификация в реестре

Status: active


        Спецификация — около пяти тысяч строк markdown. Ревью и аудит нашли в
        ней утверждения, отменённые решениями, но оставшиеся в тексте, и
        пережимы уникальности сверх механизма. Текст, который ничто не
        проверяет, разошёлся с решениями за один день.

        Рассматривались три объёма: только утверждения в реестре при
        пояснениях в markdown; только гарантии и гипотезы; полный перенос.
    

## Decision


        Полный перенос: нормативный текст частей I–VIII живёт в записях
        реестра, markdown порождается рендером и руками не правится.

        Перенос идёт по частям, и перенос нормы есть её ревью: норма получает
        точку принуждения и честный статус, отменённое не переносится. Рендер —
        первый срез направления: до него спецификацию нельзя читать.
    

<details>
<summary>Trade-offs</summary>

- Плюс: один источник истины для текста и связей, ссылки проверяет компилятор
- Плюс: метод применяется к собственному главному документу
- Минус: до рендера спецификация читается только в исходниках
- Минус: проект первой обкатки хранит прозу решений в markdown, поэтому его обкатка не проверит наш собственный носитель
- Минус: перенос пяти тысяч строк — объём на несколько срезов

</details>
<details>
<summary>Constraints</summary>

- Порождённый markdown не правится руками; свежесть проверяется.
- Норма без точки принуждения переносится как норма без исполнителя.
- Утверждение, отменённое решением, не переносится.
- Число переносится только с командой-источником; число без источника снимается.
- Уровень L1 объявляется самодостаточным, а избыточное для малого проекта перечисляется явно.

</details>
