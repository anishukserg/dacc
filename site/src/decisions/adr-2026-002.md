# adr-2026-002 — Носитель реестра по частоте изменения

Status: active


        Решение пересматривалось дважды за один день, и обе крайности
        оказались неверны. Сначала весь реестр держался в Rust; оценка
        практика показала, что для сотен записей долга это неприменимо.
        Затем весь слой работы был отправлен в TOML; разбор показал, что из
        трёх доводов два несостоятельны — цена перехода автоматизируется,
        а нагрузка на сборку снимается тем, что реестр является листовым
        крейтом.

        Отдано при этом было главное: навигация. Ссылка-путь даёт переход в
        определение, автодополнение и поиск ссылок; строка в TOML — только
        текстовый поиск.
    

## Decision


        В Rust живёт всё, что пишет человек при планировании: решения,
        спецификации, глоссарий, опорные записи, каталог гейтов, политики,
        направления, срезы, единицы работы, долговая книга, хореография.

        В TOML — журнал событий и входящий поток: их пишет машина, десятки
        раз в день, из хуков и CI, где компиляция Rust неуместна.
    

<details>
<summary>Trade-offs</summary>

- Плюс: ссылки проверяются компилятором, работает навигация IDE
- Плюс: события журнала пишутся из любого окружения без тулчейна
- Минус: изменение реестра требует пересборки листового крейта
- Минус: два носителя вместо одного — граница требует объяснения

</details>
<details>
<summary>Constraints</summary>

- Реестр обязан быть листовым крейтом: продуктовые крейты от него не зависят.
- Журнал не переводится в Rust ни при каких настройках.

</details>
