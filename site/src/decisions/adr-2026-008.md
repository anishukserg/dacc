# adr-2026-008 — Правила коммитов: форма сообщения, основание из плана, явные пути, проверка дерева коммита

Status: active


        Работа обязана иметь основание, готовность — доказательство. До
        журнала единственная запись о сделанном — история git, и держится она
        ровно настолько, насколько дисциплинированы коммиты.

        Известные отказы коммитов при работе агентов: словарь типов в теме
        расползается синонимами, если форма не проверяется; `git add -A` в
        общем дереве забирает чужие изменения; проверка, спрятанная за «если
        инструмент установлен», молча выключается; хук печатает сотни строк,
        из которых нужна одна; проверка рабочего дерева при частичном коммите
        подтверждает не то дерево, которое уходит в историю.
    

## Decision


        Тема — `[ТИП](область): суть`: тип из закрытого набора FEAT, FIX,
        REFACTOR, TEST, DOCS, ADR, PLAN, CHORE; область — значения оси
        подсистем в нижнем регистре через запятую; не длиннее 72 символов, без
        точки в конце. Каждый коммит несёт трейлер `Dacc-Work: wNNNN`, и
        единица работы обязана существовать в дереве этого коммита; коммит
        закрытия среза вместо него несёт `Dacc-Slice: sNNNN` (решение 15).

        Коммит делается командой `cargo dacc commit` (решение 14):
        сообщение проверяется до блокировки и хуков, пути перечисляются явно,
        параллельный коммит ждёт блокировку, вердикт — последней строкой
        `COMMIT OK <sha>` или `COMMIT REFUSED: <причина>`; «отвергнут» и
        «нечего коммитить» имеют разные коды.

        Хук pre-commit выгружает дерево коммита и гоняет на нём калитку
        `cargo dacc gate`: внешние имена по локальному списку; относительные
        ссылки в markdown; форматирование; clippy без предупреждений; сборку
        всех целей с константными проверками реестров, тесты и атаки с полом по
        числу прошедших doctest; документацию без битых ссылок; проверки
        решений 12 и 13. Тулчейн и его компоненты закреплены в
        rust-toolchain.toml. Отсутствующий инструмент — отказ, а не пропуск;
        отсутствующий список внешних имён — шаг, названный невыполненным. Сами
        правила покрыты тестами инструмента, которые калитка выполняет на
        каждом коммите.

        Хук pre-push не выпускает в удалённый репозиторий ветки архива и
        историю, в дереве или сообщениях которой есть имя из локального списка
        внешних проектов.
    

<details>
<summary>Trade-offs</summary>

- Плюс: основание коммита проверяется по дереву коммита, а не по памяти автора
- Плюс: частичный коммит проверяется тем деревом, которое уходит в историю
- Плюс: ссылки в документации проверяются так же, как ссылки в реестре
- Минус: калитка на каждом коммите стоит секунд сборки, clippy и тестов; бюджет — 60 секунд на прогретом кэше
- Минус: хуки обходятся флагом --no-verify, а удалённого CI у репозитория нет

</details>
<details>
<summary>Constraints</summary>

- Без явных путей коммит не делается: `git add -A` без путей, `git add .` и `git commit -a` запрещены.
- `--amend`, переписывание истории и `--no-verify` — только по явной просьбе владельца репозитория.
- Калитка, превысившая бюджет, делится на слой коммита и слой закрытия работы, а не выключается.
- Пол числа doctest в калитке только растёт; понижение — изменение правила с ревью.

</details>
