# adr-2026-042 — Жизненный цикл работы — события started, gate и landed в одном коммите приземления

Status: active


        Церемония работы — три коммита: work start пишет событие started, затем
        контентный коммит, затем work land пишет gate и landed. Пилот nerpa
        зафиксировал налог: около сорока коммитов на двенадцать логических
        изменений, и половина — церемония. Событие started не несёт решения и
        не меняет доказательство, а только занимает отдельный коммит.

        Нужно сжать started/gate/landed в один коммит, не потеряв доказательство
        на дереве и не нарушив неизменность события (решение 15).
    

## Decision


        Команда work start перестаёт быть отдельным коммитом: событие started
        пишется командой work land вместе с gate и landed, в одном коммите.
        Автомат сохраняет порядок «started → gate → landed», и свёртка
        обрабатывает три события одного коммита по порядку, поэтому работа
        переходит из «запланирована» сразу в «приземлена» — промежуточное
        состояние «начата» отдельным коммитом больше не наблюдается.

        Доказательство не меняется: gate по-прежнему исполняется на дереве
        контента, и его хэш — в событии gate; landed требует gate с тем же
        деревом (решение 15).

        Церемония становится двумя коммитами на изменение: контентный коммит и
        коммит приземления. Время события started — время приземления: потеря
        «когда начали» принята, потому что ход работы виден по контентным
        коммитам, а started только помечает, что работа велась.
    

<details>
<summary>Trade-offs</summary>

- Плюс: церемония — два коммита на изменение вместо трёх
- Плюс: доказательство на дереве и неизменность события не меняются
- Плюс: автомат свёртки остаётся прежним — события одного коммита читаются по порядку
- Минус: время события started совпадает с приземлением, «когда начали» отдельно не хранится

</details>
<details>
<summary>Constraints</summary>

- started, gate и landed пишутся одним коммитом командой work land.
- Доказательство по-прежнему привязано к хэшу дерева контента.
- Свёртка читает события одного коммита по порядку started → gate → landed.

</details>
